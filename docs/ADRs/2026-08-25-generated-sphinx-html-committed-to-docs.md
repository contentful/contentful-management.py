# Generated Sphinx HTML is Committed to `docs/`, Sources Live in `_docs/`

## Date

2026-08-25

> This record was written on 2026-08-25 from the repository contents and commit
> history. It documents an existing, long-standing decision rather than a new
> one. The rationale below is reconstructed from what the repo does — no
> contemporaneous design discussion was available.

## Status

Accepted

## Context

The library's API reference is built with Sphinx. Two directories are involved,
and their names invert the usual convention:

- `_docs/` — Sphinx **sources**: `conf.py`, `index.rst`, `Makefile`,
  `make.bat`, plus `contentful_management.rst` and `modules.rst`, which are
  themselves regenerated by `sphinx-apidoc`. `_docs/conf.py` still carries its
  `sphinx-quickstart on Wed Nov 30 12:51:32 2016` header, so the Sphinx setup
  predates most of the current codebase.
- `docs/` — the **built HTML output**, committed to the repository: 112 tracked
  files at the time of writing, including `docs/index.html`,
  `docs/contentful_management.html`, and the Sphinx asset trees `docs/_static/`,
  `docs/_modules/`, and `docs/_sources/`.

Only `_docs/_build/` is ignored (`.gitignore`, "Sphinx documentation" section).
The copied-out `docs/` tree is deliberately tracked.

`docs/.nojekyll` is present. That marker is what GitHub Pages requires in order
to serve paths beginning with an underscore — without it, Jekyll would skip
`docs/_static/`, `docs/_modules/`, and `docs/_sources/`, and the rendered
documentation would lose its stylesheets and source links. Its presence
indicates the committed `docs/` tree exists to be served from the default
branch, not merely archived.

Regeneration is wired into release, not into CI. `pyproject.toml` →
`[tool.pdm.scripts]`:

```
docs      → sphinx-apidoc -o _docs/ contentful_management
            make -C _docs html
            rm -rf docs
            cp -r _docs/_build/html docs
git-docs  → composite: docs, git add docs, git commit --amend -C HEAD
release   → composite: clean, git-docs, pdm publish
```

`.github/workflows/ci.yml` runs only `pdm run coverage` and `pdm run lint`
across Python 3.9–3.12; it never builds or verifies the docs. The evidence that
`docs/` is refreshed at release time is in the version-bump commits themselves:
`ab7f607` ("Bump to version 2.16.0") touches `CHANGELOG.md`,
`contentful_management/__init__.py`, and the whole `docs/` HTML tree in one
commit — the signature of `git-docs`' `commit --amend`. The same shape appears
in `338451b` (2.15.2), `2fc293c` (2.15.1), `7de147c` (2.15.0), and `c8ee03f`
(2.14.6).

## Decision

Keep Sphinx sources in `_docs/` and commit the built HTML to `docs/` on the
default branch. `docs/` is generated output under version control: it is
produced only by `pdm run docs`, and it is refreshed as part of `pdm run
release`, folded into the version-bump commit by `pdm run git-docs`.

`docs/` is therefore not hand-editable. Documentation changes are made in
`_docs/` (or in the Python docstrings that `sphinx-apidoc` reads) and reach
`docs/` only through a rebuild.

## Consequences

- Committing build output makes release diffs large and noisy: a one-line
  behaviour change plus a version bump rewrites dozens of HTML files. Reviewers
  need to read past the `docs/` churn to find the substantive change.
- Documentation is only as fresh as the last release. Because CI never builds
  the docs, a merged change to a docstring is not reflected in `docs/` until
  someone runs `pdm run release`. There is no check that would catch the drift.
- `pdm run docs` starts with `rm -rf docs`. **Anything added to `docs/` by hand
  is deleted by the next docs build, including this directory.** The AI harness
  readiness controls require decision records under `docs/ADRs/`, so this record
  lives inside a directory that the release process wipes. Until the `docs`
  script is changed to preserve `docs/ADRs/` (or the control accepts another
  location), whoever runs a release must re-add `docs/ADRs/` afterwards.
- `pdm run docs` ends with `open docs/index.html`, a macOS-only command. The
  script fails on Linux and inside the dev container after the HTML has already
  been written, so `git-docs` and `release` are effectively macOS-local
  operations.
- The `_docs/` (source) versus `docs/` (output) naming is the reverse of what
  most Python projects use, and is a documented sharp edge in `AGENTS.md`.
